# Windows backend

`rustgfw windivert <WinDivert.dll 路径> <network|forward> <accept|drop> [规则...]` 使用与 Linux 相同的传输层规则、HTTP Host、TLS SNI 和 DNS 分析器。`network` 捕获本机收发，`forward` 捕获经过本机的包。WinDivert 2.2 负责抓包、裁决和原包重新注入；本机模式会尝试将 `DropFlow` 下沉到 WFP，无法下沉时由用户态后续逐包执行。

动态 WFP 监听在直接指定 HTTP Host、TLS SNI、DNS 名称，或表达式可能产生 `DropFlow` 时启动。表达式的 `block` 动作可阻断 TCP/UDP 流，TCP 上的 `drop_packet` 也会阻断整个流；仅用于 UDP 的逐包丢弃与载荷替换不会启动该监听。

WinDivert 的 `Recv` 把包从网络路径取出；接受必须调用 `Send` 重新注入。适配器保留完整的 80 字节 `WINDIVERT_ADDRESS`，使方向、接口和校验和标志随原包返回。丢弃不调用 `Send`。两个模式的用户态流都以双向五元组为作用域：WinDivert 的 `IfIdx/SubIfIdx` 描述收发接口，出站重注入时这些字段会被忽略，且连接两个方向未必走同一接口；按接口编号分流可能使请求和响应无法共享 `DropFlow` 结果。仅凭五元组仍可能混淆不同网络域中的重叠连接；需要可靠的 compartment 身份后才能进一步隔离。默认放行时，有效 ICMP/ICMPv6 直接走系统路径，分片仍进入引擎；这避免 WinDivert 对部分入站 ICMP 原包重注入失败而让引擎退出。默认丢弃仍捕获全部协议。在 `network` 与 `forward` 层使用同一决策接口。依据：[WinDivert 2.2 手册](https://reqrypt.org/windivert-doc.html)。

`network` 模式启动时，将有序规则开头连续的 `drop` 规则下沉到 WFP 本机连接授权层；遇到第一条 `accept` 就停止，避免改变优先顺序。协议与本机/对端端口分别匹配 IPv4/IPv6 的 `ALE_AUTH_CONNECT`、`ALE_AUTH_RECV_ACCEPT`，所有过滤器在一个事务中提交，动态会话结束即清除。WFP 初始化失败时记录原因并继续由 WinDivert 执行规则。此静态下沉尚未经过真实 WFP 流量测试。[各过滤层可用条件](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-conditions-available-at-each-filtering-layer)、[过滤器仲裁](https://learn.microsoft.com/en-us/windows/win32/fwp/filter-arbitration)。

`forward` 模式没有本机 socket 的 ALE 身份，而且 WFP `IPFORWARD` 层没有 TCP/UDP 端口条件。因此转发模式用优先级 1 的 WinDivert `DROP` 句柄执行同一段开头的静态丢弃规则；优先级 0 的普通句柄继续捕获其余包作用户态检查。静态句柄安装失败时仍由普通句柄逐包执行。WinDivert 的转发层与 Windows NAT 存在已知限制，实际转发部署需要单独验证。[WinDivert 过滤器、优先级与 DROP 标志](https://reqrypt.org/windivert-doc.html)。

`wfp::WfpPolicy` 还提供精确本机连接阻断规则的安装/撤销接口；每条流的两个方向同事务提交。`LocalFlow` 用 `LocalScope` 限定网络域：可指定 compartment ID，也可将被截获包的接口索引转换为 LUID，匹配 WFP 看到的本机 IP 所属接口。过滤器还匹配双端地址、端口和协议；但本机 IP 所属接口未必等于被截获包的接口，需要真实流量核实命中。IPv4 地址和端口按 WFP 要求使用主机字节序。`flow::FlowEvents` 使用 WinDivert FLOW 层接收建立/删除事件，解析端点 ID、双端地址、协议和进程 ID；FLOW 事件不提供 compartment ID 或接口索引。启动时先打开 FLOW 监听，再打开网络包句柄。收到 `DropFlow` 后，工作线程只对已观察到唯一端点 ID 的同五元组安装规则；重叠端点出现时撤销该五元组已有的动态规则，端点删除时撤销其规则。FLOW 监听出错时关闭动态 WFP 会话，用户态继续裁决。监视句柄关闭时使用 `WinDivertShutdown(RECV)` 唤醒读取线程。动态过滤器增加 `IS_REAUTHORIZE` 条件：策略变更后已有 ALE 流的下一包重新授权时可阻断，而新连接首次授权不会命中遗留的过滤器。每条动态规则在安装 5 分钟后到期，工作线程每 30 秒检查一次；撤销后该连接继续由 WinDivert 逐包阻断，防止 FLOW 删除事件静默丢失时规则无限期残留。到期前的重授权仍可能受遗留规则影响，须经真实驱动和故障测试确认。转发包需要单独设计匹配范围。依据：[WinDivert FLOW 层与关闭语义](https://reqrypt.org/windivert-doc.html)、[WFP 各层可用条件](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-conditions-available-at-each-filtering-layer)、[ALE 重新授权](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-re-authorization)、[WFP 条件标志](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-condition-flags-)、[WFP 对象生命周期](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management)、[WFP 条件字节序](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-condition-identifiers-)。
